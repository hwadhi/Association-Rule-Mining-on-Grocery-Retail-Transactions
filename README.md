# Association Rule Mining on Grocery Retail Transactions

Market-basket analysis of a 7,501-basket grocery dataset with Apriori and FP-Growth, including a basket-size randomisation null model, redundancy analysis, network visualisation and a business interpretation.

**Main deliverable:** `association_rule_mining.ipynb` (fully executed; 15 numbered sections).
A static HTML copy is in `outputs/reports/association_rule_mining_report.html`.

## Overview

The notebook takes one CSV file and carries it from raw inspection to a shortlist of interpreted association rules. Every number quoted in the notebook's text comes from the executed code; every table and figure is regenerated by running the notebook from the original CSV.

## Problem statement

Given 7,501 grocery baskets over about 120 products, determine (i) which products and product combinations are frequently bought together, (ii) which co-purchase rules are statistically meaningful *beyond item popularity and basket size*, and (iii) what these patterns do and do not justify in merchandising terms.

## Dataset description

| Property | Value |
|---|---|
| Original file | `store_data_association_rules.csv` (stored unchanged as `data/original_dataset.csv`) |
| Layout | Wide format, comma-separated, ragged rows, **no header row**: line 1 is a real 20-item transaction |
| Rows / columns | 7,501 baskets / 20 positional item slots (blank = unused slot) |
| Items | 120 raw strings, 119 after trimming one leading-space defect |
| Item occurrences | 29,363 raw, 29,358 after collapsing 5 repeated items within a basket |
| Basket size | mean 3.91, median 3, maximum 20; 1,754 single-item baskets (23.4%) |
| Absent fields | transaction ID, customer, timestamp, quantity, price, category |

Loading with the pandas default (`header=0`) would silently drop the first basket; the notebook detects and documents this.

## Objectives

O1 establish structure and quality; O2 build valid transactions; O3 mine frequent itemsets with two algorithms; O4 justify thresholds; O5 generate and rank rules with seven metrics; O6 reduce noise without blind deletion; O7 interpret responsibly (association, interpretation, recommendation and hypothesis kept separate). All are addressed in Section 15.3 of the notebook.

## Methodology

1. Faithful loading (encoding and delimiter detection, `header=None`, everything read as strings).
2. EDA on the raw table (structure, quality, blank slots, duplicates, basket sizes, item frequencies, Pareto).
3. Minimal, documented cleaning (trim whitespace, two spelling corrections, repeated items collapsed); duplicates, rare items, large baskets and single-item baskets are kept.
4. One row = one transaction (item set); validation against the raw table.
5. Sparse one-hot encoding (`TransactionEncoder`) with full decode-back validation.
6. Frequent itemsets with Apriori and FP-Growth over 11 minimum-support thresholds; chosen threshold 0.5% (38 baskets).
7. Rule generation (1,940 rules), metrics validated against manual recomputation.
8. Rule selection (confidence >= 0.20, lift >= 1.2: 562 rules), redundancy flags, naive and **curveball null-model** significance (500 randomisations preserving basket sizes and item counts), final shortlist of **217 rules**.
9. Visualisation (static and interactive), Apriori vs FP-Growth comparison, business interpretation, conclusions.

## Algorithms

* **Apriori** and **FP-Growth** (`mlxtend` 0.25.0) for frequent itemsets; `association_rules` for rules.
* Metrics: support, confidence, lift, leverage, conviction, Zhang's metric, plus *excess lift* (observed lift / null-model mean lift).
* Curveball randomisation, hypergeometric test and Benjamini-Hochberg FDR control for reliability.

## Important findings

* The first line of the file is a basket, not a header: 7,501 transactions, 119 products, short baskets (mean 3.91).
* At 0.5% minimum support there are **725 frequent itemsets** (101 / 451 / 173 items of size 1 / 2 / 3); Apriori and FP-Growth are identical.
* **Lift above 1 is the default in this data.** A randomisation null model preserving basket sizes and item counts gives lift above 1 for all 1,940 rules (median 1.49), and the full pipeline on null data returns about 480 "selected" rules versus 562 in the real data. Selection thresholds alone therefore do not identify real associations.
* After redundancy, significance and excess-lift filtering, **217 rules** remain. The best-supported involve ground beef (with spaghetti, mineral water, seasoning), burgers with eggs, and olive oil with spaghetti. The highest-lift rules (pasta with escalope or shrimp, whole wheat pasta with olive oil) rest on 38-60 baskets and are tentative.
* Popular pairs such as eggs with mineral water are explained by popularity; cookies and mineral water are negatively associated.
* FP-Growth is up to roughly 9-12 times faster and far leaner than Apriori at low support; Apriori is only faster near a 2% minimum support.

## Limitations

No transaction IDs, timestamps, customers, quantities or prices; one store and period of unknown origin; baskets treated as sets; thresholds (0.5% support, confidence 0.20, lift 1.2, q < 0.05) are judgements; the null model removes all size-related effects and has a smallest attainable q-value of about 0.012 with 500 randomisations; negative associations and very rare items below the support floor are invisible; benchmarks come from one machine and library implementation; **rules describe association, not causation**. See Section 15.5 of the notebook.
